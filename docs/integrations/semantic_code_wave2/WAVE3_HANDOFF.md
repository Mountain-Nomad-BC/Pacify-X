## Wave 3 responsibilities

Wave 3 is where semantic evidence begins to participate in PX-wide governance and context:

- capability projection and admission for different clients/models;
- authority inspection before semantic actions are exposed;
- read-only cross-project semantic queries with explicit project isolation;
- provenance/query receipts tying a model request to the evidence it consumed;
- Atlas/project-map/knowledge evidence bridges;
- controlled context/mode projection for local models and external clients;
- bounded semantic evidence surfaces that later memory, retrieval and orchestration waves can consume.

## Tiny internal operator requirement

The resident tiny model is no longer treated as a classifier-only lane. Its eventual role is the PX librarian/concierge/grunt worker: query knowledge and skills, fetch semantic evidence, assemble bounded context, trigger admitted learning conditions, request graph/map refreshes, perform queued scripted work and escalate difficult reasoning to the deep model.

Wave 3 should therefore expose **capabilities**, not raw internals. The operator may be granted a contract such as “query symbols/references for this admitted project” without receiving the ability to choose a language-server executable, mutate files, rewrite authority data or bypass orchestration.

## Authority line

LSP servers remain semantic sensors and edit-proposal engines. Neither an LSP server nor the tiny internal model becomes authority over Atlas, memory, knowledge truth, permissions, certification or repository state. Those decisions stay with PX contracts and deterministic owners.
