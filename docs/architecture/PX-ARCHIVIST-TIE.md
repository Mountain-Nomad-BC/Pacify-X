# PX Archivist and T.I.E.

PX Archivist is the PX orientation, classification and retrieval role. Its model size is a deployment choice, not its identity. The agent console uses the `PXArchivist` class; `TinyLibrarian` remains a compatibility export of that class. Existing `px.librarian-artifact/1.0`, event names, persisted keys and source tags remain compatibility identifiers pending governed migration. A deterministic classification is explicitly labelled as a fallback, not evidence of small-model inference.

The normal semantic map now registers logical source identifiers with `EntityRegistry` and stores their physical positions in `LocatorRegistry`. Callers can resolve canonical IDs or existing compatibility keys. Proposed semantic records do not inherit acceptance from an asset's status. Derived graph IDs require explicit binding to an admitted source entity; unresolved bindings remain visible and block complete rename coverage.

The map generation includes current operational facts, relationships, canonical records, locators and unresolved identity conditions. A changed description or source locator changes the generation; changing the locator does not change the logical entity identity. Duplicate declarations fail explicitly.

T.I.E. — **Tenacious Integrated Experiences** — describes validated operational experience retained by an object through its use.

| Operation | Required behavior |
|---|---|
| TIE record | Attach experience to the canonical object identity, with provenance and scope. |
| TIE update | Add newly validated operational experience; an unverified observation remains a candidate. |
| TIE retrieval | Retrieve relevant permitted prior experience before execution, bound to current context. |
| TIE propagation | Promote validated experience to related objects through governed authority. |
| TIE isolation | Prevent a local object's quirks from becoming unqualified global behavior. |
| TIE refinement | Convert repeated validated experience into a proposed, independently verified improvement. |

The continuity sequence is preserve experience → migrate → reconcile → rebuild context → reintegrate → continue operating. Migration must retain object identity, privacy controls and provenance; stale context must not silently become execution authority.

These TIE semantics are owner requirements for adapting the existing memory fabric, vault, broker, operations and intelligence owners in W4–W5. This document does not claim their implementation is complete. Shared chat/model collaboration follows execution prerequisites in W3 and integrated graph/provider/routing work in W6. `.agentic_engineering_os_px` storage migration remains W2 work after semantic coverage. Builds and installs remain on owner hold.

The current Archivist metadata consumer uses the shared `ContextGenerationVector` and `ProjectionGate` owners. Its vector binds the project and metadata scope to source, semantic and projection generations; observed authority/policy revisions are retained. Unobserved runtime epochs, model/retrieval generations and execution graph revisions remain null. A fresh metadata description does not grant execution authority. Retained maps recheck their bounded metadata inputs and reject changed sources. Degraded reads require an explicit trusted host policy; protected authority drift and missing required components cannot be waived. Full cross-consumer generation integration remains W1 work.

Compact references pair a canonical alias with the SHA-256 of the exact project-scoped address table. Bare aliases are rejected; references from another table cannot silently resolve to a reused address. A locator move preserves logical identity and its alias when the entity set is unchanged. Descriptions expose locator-derived `located_at` relations; arbitrary graph edges remain separate until their endpoints and relation meaning are explicitly admitted. Returned canonical metadata is defensively copied, and stored identity bases are immutable. These metadata references confer no execution authority.
