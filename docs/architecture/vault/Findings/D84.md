# Certification and complete are separate producer fields

**Historical finding; current closure not revalidated.**

The UI gives certified plus fresh first precedence. Tracing upstream narrows the initial concern: build_completion_status requires no gate blockers before freshness and certified can become true, so it does not normally emit certified/fresh with current_gates false. complete is separately derived from blocking_reasons, including historical acceptance. Dashboard verifies stored ledger/engine/source bindings and clears green claims on mismatch. Do not label the UI precedence alone a proven certification fault.
