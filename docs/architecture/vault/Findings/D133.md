# Write-intent deduplication does not make handlers execute exactly once

**Historical finding; current closure not revalidated.**

Queue key binds project/operation/payload, but flush calls handler(operation,payload), then writes receipt and moves pending intent. There is no queue lock or atomic commit spanning handler and receipt. A handler effect followed by receipt failure leaves replayable pending work, and concurrent flushes can call the same handler. No failure/concurrency injection was executed.
