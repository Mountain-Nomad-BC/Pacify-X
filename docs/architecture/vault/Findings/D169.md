# Archive verification does not recheck source tree before removal

**Historical finding; current closure not revalidated.**

Both archive scripts verify ZIP membership, manifest and member hashes, then recheck selected top-level containment before direct rmtree. They do not compare current source file inventory/bytes with the archived manifest immediately before removal, and do not hold a producer lock or use ResourceManager. A newly added/changed source entry after archive verification is a source-inferred preservation gap. Receipt follows all deletions.
