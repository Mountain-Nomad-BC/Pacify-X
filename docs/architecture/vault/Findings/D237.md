# Service hydration budgets bound returned bodies after complete reads

**Historical finding; current closure not revalidated.**

hydrate_service_skills first materializes all IDs, then reads each full file and hashes it before checking cumulative max_bytes. It does not validate positive max_records/max_bytes or require a successful route result. Body identity comes from catalog SHA; catalog validates counts/status but not contained ID syntax. These are trusted catalog and caller boundaries, not observed external execution.
