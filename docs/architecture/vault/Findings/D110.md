# Git context conflict count is computed after change capping

**Historical finding; current closure not revalidated.**

gitSnapshot retains at most maxChanges rows and then counts conflicts from that retained list. An unmerged path beyond the cap is therefore omitted from conflicts even though staged/unstaged totals scan retained command output. The subprocess wrapper also keeps only the last200000 stdout characters without a truncation flag, potentially losing branch/status prefix. gitConflictDecision depends on that conflicts field and operation markers. This is source-derived, not a reproduced missed-conflict event.
