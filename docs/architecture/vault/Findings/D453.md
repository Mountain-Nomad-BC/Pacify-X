# Operational batches are sequential commits rather than atomic ingress

**Historical finding; current closure not revalidated.**

publish_batch caps1000 events then calls publish independently. Later invalid input leaves earlier events committed, and concurrent publishers can interleave between batch members. CLI caps ingress bytes and overwrites previous hash using link_current_head; this authenticates local chain placement, not the external event producer. There is no cross-event lifecycle or unique event-ID guard.
