# Durable persistence can remove current state before replacement succeeds

**Historical finding; current closure not revalidated.**

persist_state validates existing source version, moves it into history, then writes replacement exclusively. It does not validate the new dataclass payload before writing and lacks owner lock, rollback or fsync. A replacement failure can leave only history, and a newly written malformed payload can fail subsequent load.
