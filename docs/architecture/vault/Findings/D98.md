# Shared exact-target claims conflict with the global fence invariant

**Historical finding; current closure not revalidated.**

Overlap logic permits shared/shared claims on different tasks. claimTask increments one fencing_by_target counter for each exact target without updating earlier active claim tokens. If two shared claims request the identical target string, the prior claim token is now behind the global counter and next-state validation rejects active-claim-fence-not-current. The existing shared-mode test uses ancestor/descendant target strings with different counter keys, so it does not cover this composition.
