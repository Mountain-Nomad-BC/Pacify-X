# Native input crash can leave an effect without durable replay protection

**Historical finding; current closure not revalidated.**

last_sequence advances after successful SendInput, before result write, and resets to zero at server startup. A crash after input but before durable result can permit replay on restart. Partial SendInput raises a refusal after some key events may have occurred. Result temp name uses PID and stale temp can block publication; no fsync or write-ahead intent exists.
