# Memory revision validation follows filesystem path order

**Historical finding; current closure not revalidated.**

records iterates sorted recursive paths and requires the next per-ID revision immediately. append chooses category/address/directory from current type/title/key and does not require those fields unchanged. A revision whose new path sorts before its predecessor can therefore fail subsequent chain reads; prior_payloads[-1] also depends on path order. Existing tests exercise different IDs and duplicate revision rejection, not title-changing same-ID history. This is a source-inferred branch, not an executed reproduction.
