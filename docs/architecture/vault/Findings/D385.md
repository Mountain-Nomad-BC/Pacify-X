# Foundry materialization has partial publication and duplicate output identities

**Historical finding; current closure not revalidated.**

Materializer creates destination/bundle_id before rendering/writing sorted files and publishes receipt last. Failure leaves an unregistered partial directory that normal retry refuses. Duplicate calculation IDs overwrite entries in the file map while bundle metadata retains both. Supplied bundle/skill IDs are used as path components without separate validation; compiler-produced slugs are narrower than direct dataclass inputs.
