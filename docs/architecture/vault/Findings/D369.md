# Memory timeout bounds waiting but not callback effects or aggregate concurrency

**Historical finding; current closure not revalidated.**

StateKVGuard creates a new executor per call and shutdown(wait=False) cannot stop an already-running callback. Breaker state has no lock and uses invocation-start time for failures, so long calls can consume the cooldown before failure is recorded. Concurrent calls can race success/failure resets; no central worker or resource custody bound is present.
