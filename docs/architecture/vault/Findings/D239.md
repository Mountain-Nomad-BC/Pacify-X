# Project retrieval result caps are not full computation or context-byte bounds

**Historical finding; current closure not revalidated.**

top_k and relation_depth are validated, but entire JSON is read/scored, relation expansion has no frontier cap, and returned summaries/relations have no byte cap. Hydration files/context lines are not range-validated. Duplicate IDs overwrite relation lookup; negative posting indices are not rejected. These inputs come from the promoted index and are not fully schema-checked here.
