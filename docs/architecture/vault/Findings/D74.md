# A resumed release can finish its journal while its aggregate remains invalid

**Historical finding; current closure not revalidated.**

execute_all starts a new stages list and calls next_pending_step, which skips and verifies earlier passed stages. Its final valid compares this invocation list length to the entire 12-stage STEP_ORDER. Therefore a resumed call with prior passed stages can finish the journal but return valid false and count only newly executed stages. This is source-derived behavior, not a product reproduction.
