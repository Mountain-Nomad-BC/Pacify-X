# Python work timeout is admission waiting time, not producer execution time

**Historical finding; current closure not revalidated.**

RuntimeWorkPlane uses timeout_seconds while acquiring operation lock and later pool slot, each with its own wait clock. Once admitted it calls producer() synchronously with no timer/cancellation wrapper. Thus the dashboard60-second work-plane argument does not itself impose a60-second runtime ceiling; an outer host subprocess timeout is a separate mechanism.
