# Process receipt identity omits mutable compilation inputs

**Historical finding; current closure not revalidated.**

Receipt filename hashes the process record only, while compilation also reads current catalog and stores project/apply metadata. Repeating after catalog changes can trigger receipt drift under the same process hash. Receipt write precedes project state parse/schema validation/write; no joint transaction, lock or state CAS protects that update. Project commissioning is checked by file existence first.
