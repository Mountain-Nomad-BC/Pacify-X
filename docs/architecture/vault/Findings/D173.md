# Lock finalization can fail after protected work committed

**Historical finding; current closure not revalidated.**

FileLock retains heartbeat I/O error until __exit__, writes released metadata, unlocks/closes and raises release_error if the body succeeded. Thus a caller may receive an exception after its protected state writes completed. A failed release write can retain held metadata naming a still-live process and block later acquisition even though the OS lock is free.
