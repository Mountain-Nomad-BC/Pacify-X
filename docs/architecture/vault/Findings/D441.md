# Retrieval readiness binds result summaries rather than the complete evaluation policy

**Historical finding; current closure not revalidated.**

Readiness correctly rejects duplicate top-k results, absent relevance judgments and observed forbidden IDs. However it materializes full result sequences before slicing; leakage beyond k is outside scope. evaluation_sha256 includes rows/metrics but excludes threshold values, full judgments and actual ranked IDs. Identical summary hash can therefore accompany different readiness decisions. activation_allowed is a returned recommendation, not a backend activation.
