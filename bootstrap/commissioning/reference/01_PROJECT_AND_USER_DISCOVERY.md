# Project and user discovery

Capture the problem, intended users, current workflow, desired outcome, scope, non-goals, roles, misuse cases, data sources, source-of-truth rules, success measures, constraints, timeline, budget, and existing assets. Label every entry as confirmed fact, preference, assumption, unknown, contradiction, recommendation, or decision requiring approval.

Ask only questions whose answers can change scope, architecture, risk, cost, operations, accessibility, or acceptance. Do not begin implementation until the resulting brief is approved.
