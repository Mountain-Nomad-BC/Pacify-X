# Govern Candidate Resolution Pipeline

1. Inventory and profile every source before extraction. Keep partial, malformed, poisoned, or license-uncertain inputs quarantined and reasoned.
2. Compile deterministic intermediate artifacts with separate glossary, pattern, procedure, provenance, and on-demand shard roles. Generated metadata cannot grant tools or widen authority.
3. Scan the resolved generated artifact, reject symlinks and invisible control text, bound bytes, and report finding codes without echoing attacker-controlled text.
4. Classify fold-in at claim and shard granularity as duplicate, enrichment, revision, conflict, or manual review. Bind every proposal to source and target fingerprints; do not overwrite a complete skill by default.
5. Execute the eleven canonical resolver stages in order. Hydrators and scorers preserve candidate identity, count, and order. Only discovery, filters, and selection may change membership.
6. A required component failure blocks. An optional failure explicitly abstains and emits evidence; it never becomes a positive default.
7. Score each candidate using only the task, authorized context, and that candidate. Prove unrelated batch additions do not alter intrinsic scores.
8. Select by marginal utility under capability, required-kind, dependency, authority, evidence, rollback, token, cost, and diversity constraints. Preserve a reason for every excluded candidate.
9. Treat served-history approximations as advisory. Required candidates and exact outcome evidence override likely-seen signals; never learn success from selection alone.
10. Generate host projections from canonical meaning and authority. Host metadata cannot mutate either.
11. Certify with held-out expected/forbidden cases, batch-stability, saturation, dependency, budget, partial-source, poison, fold-in, portability, and discovery-cost tests.

Use `runtime.completion_controls.validate_candidate_stage_trace`, `verify_batch_independent_scores`, and `optimize_candidate_package` as the deterministic enforcement boundary. Canonical application remains approval-bound and non-destructive.
