# Model and data gate

The admission ledger records dataset version, record IDs, content hashes, source identities, license or written authority, consent, purpose, labels, split, subject grouping, sensitive-data review, transformations, and exclusions.

Prevent the same content or subject from crossing train, validation, and test boundaries. Use independently owned fixtures for acceptance tests. Report empty inputs, constant distributions, non-finite values, class gaps, and distribution shift rather than silently normalizing them.

Treat training, conversion, model loading, network downloads, process execution, and promotion as separate effects. Each needs pinned inputs, resource bounds, an idempotency key, current evaluation evidence, artifact hashes, and rollback. A dataset passing metadata admission is not proof of model quality or deployment safety.
