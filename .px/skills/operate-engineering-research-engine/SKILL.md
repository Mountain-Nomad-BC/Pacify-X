# Operate Engineering Research Engine

1. Normalize the research question, source classes, acceptance criteria, search budget, licenses, and prohibited reuse before discovery.
2. Queue discovery deterministically with source, query, retry, and deduplication receipts. Search breadth does not imply admission.
3. Fingerprint repository structure and content hashes. Track version drift without equating a repository name with a stable mechanism.
4. Score engineering evidence using explicit dimensions such as test depth, maintenance, documentation, reproducibility, security, portability, and source authority. Keep unknowns visible.
5. Extract mechanisms with inputs, outputs, invariants, failure modes, evidence locators, and provenance. Collect mechanisms, not repositories.
6. Build a bounded mechanism graph, resolve duplicates and conflicts, and synthesize cross-source patterns without copying implementation text.
7. Normalize papers, repositories, standards, documentation, datasets, and experiments into the same evidence envelope while preserving source type.
8. Compare mechanisms with the canonical capability graph and issue duplicate, enrichment, revision, conflict, novel-candidate, or review deltas.
9. Route all deltas through the knowledge refinery and skill admission controller. Research cannot directly promote code, skills, weights, or authority.

Use `runtime.completion_controls.fingerprint_repository` and `synthesize_mechanism_delta`. Retain source evidence externally and keep deployable artifacts clean-room.
