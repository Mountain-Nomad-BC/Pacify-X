# Placement policy

The current placement is always a valid candidate. Measure the exact current
baseline before recommending change. Compare provider-neutral classes, include
all boundary costs, and prefer bounded adapters, sidecars, workers, projections,
or indexes before primary-system migration.

Every candidate requires compatibility, correctness, baseline, and rollback
gates. Promotion requires exact before/after benchmark hashes, boundary evidence,
rollback evidence, partial-unit identity, and post-promotion monitoring. A skill
decision is advisory and never grants migration or production authority.
